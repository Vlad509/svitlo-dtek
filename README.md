# svitlo-dtek

Стежить за графіками відключень ДТЕК для кількох адрес і пише в Telegram (група та/або особисті чати):

- **Київська область** — dtek-krem.com.ua (за чергою або за адресою);
- **місто Київ** — dtek-kem.com.ua (за адресою, черга визначається автоматично).

Для кожної адреси бот:
- надсилає повідомлення, коли графік змінився або з'явився графік на завтра;
- тримає **закріплене повідомлення «актуальний графік»** і тихо оновлює його.

Технічні попередження (сайт заблокував, адресу не знайдено) йдуть лише в `admin_chat`.
Працює в GitHub Actions кожні 30 хвилин, сервер не потрібен.

## Файли

| Файл | Що робить |
|---|---|
| `targets.json` | адреси й чати (приватний репозиторій — тому тут можна) |
| `dtek_krem.py` | клієнт сайтів ДТЕК (curl_cffi з відбитком Chrome) |
| `check_schedule.py` | перевірка змін, повідомлення, закріплені повідомлення |
| `.github/workflows/dtek-schedule.yml` | розклад запуску |

Стан і графік зберігаються в гілці `data`: `state.json` і `schedule.json`
(графік адреси з `"esp": true` — для ESP32).

## targets.json

```json
{
  "chats": ["-1001234567890"],
  "admin_chat": "123456789",
  "targets": [
    {"id": "home", "name": "🏡 Дім", "site": "krem", "group": "GPV6.2", "esp": true},
    {"id": "parents", "name": "👵 Батьки", "site": "kem", "street": "вул. Хрещатик", "house": "10"}
  ]
}
```

- `chats` — куди йдуть графіки: id сімейної групи та/або особисті chat_id людей, які натиснули
  «Start» у боті. У кожному чаті буде своє закріплене повідомлення.
- Для окремої адреси можна задати власний `"chats": [...]` — тоді вона йде лише туди.
- `admin_chat` — твій особистий chat_id для технічних попереджень.
- `id` — коротка латинська назва адреси, не змінюй її після запуску.
- `site` — `krem` (Київська область) або `kem` (Київ).
- Адреса задається або `group` (черга), або `street` + `house`
  (+ `city` для області, напр. `"city": "м. Обухів"`; для Києва місто можна не вказувати).
- Вулицю й номер пиши **точно як у підказці на сайті ДТЕК**, разом із «вул.», «просп.» тощо.

## Сімейна група в Telegram

1. Створи групу (напр. «Світло»), додай батьків і свого бота.
2. Зроби бота адміністратором із правом **закріплювати повідомлення**
   (налаштування групи → Адміністратори → додати бота).
3. Напиши в групі `/start@назва_твого_бота`.
4. Відкрий `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і знайди `"chat":{"id":-100...`
   з назвою групи. Це число (з мінусом) — у `chats`.

Якщо змінюєш налаштування групи, перевір chat_id ще раз: Telegram іноді змінює його,
коли звичайна група перетворюється на супергрупу.

## Перший запуск після оновлення

Actions → DTEK schedule → Run workflow. У лозі кроку **Check schedule** для адреси побачиш:

```
[parents] м. Київ, вул. Хрещатик, 10 → ['GPV2.1']
```

- з'явились закріплені повідомлення в групі → все працює;
- прийшло попередження «не вдалося знайти адресу» → у ньому підказки (схожі номери будинків
  або «вулиця не знайдена»), виправ `targets.json`.

## Примітки

- Розклад GitHub може запізнюватися на 5–30 хв: для графіка це некритично.
- Не частіше ніж кожні 30 хв: кожен запуск рахується як ціла хвилина, і при 15 хв
  безкоштовний ліміт приватного репозиторію закінчиться.
- Якщо закріплене повідомлення видалили, бот створить нове при наступній зміні графіка.
- Без `targets.json` працює стара схема: одна черга з `DTEK_GROUP` у чат `TELEGRAM_CHAT_ID`.
- Ключ `"chat": "..."` (одним рядком) теж підтримується, як і раніше.
- Перевірка адреси вручну на своєму ПК:
  ```
  pip install curl_cffi
  python dtek_krem.py kem streets "м. Київ"
  python dtek_krem.py kem "м. Київ" "вул. Хрещатик" 10
  ```
